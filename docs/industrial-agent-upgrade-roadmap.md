# NHIS Health Agent 工业级升级路线

> 审查日期：2026-11-16
> 代码基线：`caa5825`
> 文档状态：本地实现已落地，外部发布门禁待验证。原始审查结论保留为基线记录；实施证据见 [实施与运维说明](upgrade-implementation.md) 和 [验证记录](upgrade-validation.json)。
> 适用范围：从单机研究型 MVP 升级为可持续运行、可恢复、可核验的公开研究服务。

## 1. 审查基线判断与升级原则

项目已经有较好的可信计算基础：固定 R 统计程序、受限分析规格、结果发布校验、原文证据渲染、独立盲测、访客隔离和 SQLite 原子限额。升级应保留这些机制。

目前主要差距是：用户意图可能被错误映射；任务无法在重启后恢复；模型调用链路的校验不一致；HTTP、计算与存储资源治理不足；缺少完整的研究结果发布验证。

升级遵循以下原则：

1. **先保证回答的是用户提出的问题，再保证计算和表达正确。** 合法的 `AnalysisSpec` 不代表它忠实表达了用户请求。
2. **默认值不能覆盖明确需求。** 用户未指定指标，可以使用明确的上下文；用户指定了未知指标，必须澄清。
3. **统计规则与模型生成分离。** 不开放任意 R/Python 代码、公式、路径或运行参数给模型和浏览器。
4. **执行状态必须可恢复。** 不把“线程还活着”当成唯一任务状态来源。
5. **不承诺跨外部服务的严格恰好一次执行。** 幂等应覆盖本地提交与调度；外部请求结果不确定时必须保留不确定状态。
6. **盲测保留实验语义。** 不把失败自动重试到成功，不用缓存回答替代新的注册测量。
7. **小步升级。** 每一阶段都补对应测试、兼容检查和回滚办法，不进行一次性重写。

### 优先级定义

| 优先级 | 含义 | 主要内容 |
|---|---|---|
| P0 | 扩大公开使用前必须解决 | 指标替换、约束丢失、否定反转 |
| P1 | 生产运行前需要补齐 | 持久任务、幂等、传输校验、资源边界、可观测性、发布验证 |
| P2 | 随规模与维护需求推进 | 分页归档、模块拆分、体验优化、工程规范 |

这里的 P0 表示本项目的上线阻断项，不表示已发生生产事故。

当前问题：有限关键词抽取后直接填入默认值，没有验证原始请求中的指标、人群和比较条件是否全部得到表达。部分明确研究请求会直接进入确定性研究流程，不会由 LLM planner 再次审查。

实施任务：

- [x] 将“识别用户意图”和“生成合法统计规格”拆为两步。
- [x] 在意图对象中显式保留指标、人群、分组、调整变量、包含/排除、年份与置信要求。
- [x] 增加 `recognized_constraints`、`unsupported_constraints`、`ambiguous_constraints`，并记录对应原文片段。
- [x] 执行前验证：所有明确要求均已映射，或有明确澄清/阻断结果。
- [x] 区分“未指定指标”与“指定了未注册指标”；只允许前者继承明确上下文或产品规定的默认值。
- [x] 筛选先解析为 `include / exclude / clear` 操作，再映射允许类别；不支持的否定表达转为澄清。
- [x] 通过 `AnalysisPatch` 表示追问对已有规格的修改，区分新问题、切换指标、修改分组与清除筛选。
- [x] 在执行前展示简短的实际分析范围；只有歧义时才要求用户澄清，不增加每轮确认。
- [x] 覆盖直接分析、追问、批处理、绘图触发分析等全部执行入口。

建议的中间对象，属于设计示例，不是现有 API：

```json
{
  "intent": "analysis",
  "outcome": "fair_poor",
  "group_by": "education",
  "operations": [
    {"field": "sex", "operator": "exclude", "values": ["female"]}
  ],
  "unsupported_constraints": [],
  "ambiguous_constraints": [],
  "resolution": "ready"
}
```

这里的 `ready` 仍需经过注册规则校验，不能直接作为统计执行权限。原文片段和模型解释只能辅助审计，不能单独证明意图正确。

验收标准：

- INT-01、INT-02 不调用 R、不调用独立盲测、不发布替代分析结果。
- INT-03 正确排除女性，或返回澄清；不得生成仅女性规格。
- 已支持请求及“女性呢 → 切换收入 → 去掉性别限制”等追问保持正确。
- 同义改写、否定、双重否定、矛盾条件、未知指标、未知人群均有测试。
- 在版本化评测集上，严重错误执行案例为零；这只证明该评测集通过，不宣称自然语言解析绝对可靠。

### 阶段 2：任务持久化、幂等与恢复（P1）

主要文件：[jobs.py](../nhis_agent/jobs.py)、[conversation.py](../nhis_agent/conversation.py)、[server.py](../server.py)、[access.py](../nhis_agent/access.py)。

当前问题：任务在内存字典中，使用 daemon thread；进程重启后失去任务状态。用户消息先保存、助手消息后保存，可能留下未完成回合。提交接口没有客户端幂等键。

实施任务：

- [x] 单实例先使用 SQLite 持久化 `turns / jobs / job_events / step_results / external_attempts`。
- [x] 客户端在首次提交前生成并保留 `client_message_id`；网络重试沿用同一 ID。
- [x] 用 `(workspace_id, conversation_id, client_message_id)` 唯一约束防止重复入队。
- [x] 同一幂等键、相同请求返回原任务；同一键、不同请求内容返回冲突。
- [x] 持久化任务创建、消息入库、配额预留和调度资格；避免“扣了配额但没有任务”或“未扣配额就开始付费调用”。
- [x] 增加 worker lease、心跳、步骤检查点、启动对账与优雅退出。
- [x] 已完成统计和已保存外部结果可以恢复使用，不重复产生外部调用。
- [x] 将取消请求与实际取消结果分开记录；已发出的远程调用可能无法撤销或退费。
- [x] 继续保证不同访客之间不能查询、恢复或复用彼此的任务与私有结果。

建议状态：

```text
queued → running → succeeded
                 → failed
                 → blocked
                 → cancelled
                 → unknown
```

`unknown` 用于外部请求可能已执行，但响应或本地落盘结果不可确认的情况。重启不能简单把全部 `running` 任务重新调用一遍。若供应商提供可验证的查询或幂等能力，再按该能力做对账；否则保留不确定结果和显式的新尝试记录。

盲测的每次计划调用需要独立 attempt ID。恢复后不得将失败或未知尝试静默替换为成功尝试，也不得把两次尝试当成原来的一次。

验收标准：

- 同一个提交重复发送、并发发送，返回同一任务，最多启动一个本地执行。
- 不同消息即使文本相同，也可以使用不同 ID 正常提交。
- 在提交后、R 执行中、外部调用后但结果未保存等位置终止进程，重启后状态可解释、可查询。
- 成功步骤不重复执行；外部结果不确定的步骤进入 `unknown`，不自动重发。
- 用例覆盖事务失败、配额提交失败、worker 崩溃和访客越权访问。

### 阶段 4：资源、预算、可观测性与存储治理（P1/P2）

主要文件：[server.py](../server.py)、[jobs.py](../nhis_agent/jobs.py)、[workspaces.py](../nhis_agent/workspaces.py)、[process.py](../nhis_agent/process.py)、[Dockerfile](../Dockerfile)。

#### 4.1 HTTP 与统计 worker

- [ ] 在入口代理配置连接上限、请求速率及 header/body/read timeout。
- [x] 使用有明确并发和生命周期管理的 HTTP 服务，避免无限创建请求线程。
- [x] 将 R 放入独立 worker 进程，限制并发、CPU、内存、执行时间及输出大小。
- [x] 分别管理 HTTP 连接、排队任务、统计执行和 LLM 调用的容量。
- [x] 过载时返回明确的可重试状态与等待提示，不先接受任务再无声失败。
- [x] 保留轻量存活探针；就绪信息区分聊天能力与统计能力，不仅检查配置是否存在，也不在每次探针中调用付费模型。

验收：慢连接不会无限增加应用线程；并发 R 的资源上限有效；某个 worker 失败不拖垮 HTTP 服务；关闭服务时有界退出并保存任务状态。

#### 4.2 预算与公共访问

- [x] 保留现有访客/全局消息次数上限和公共模式盲测禁用规则。
- [x] 增加每轮最大模型调用数、输入/输出 token 和统计步骤预算。
- [x] 付费调用前原子预留预算，调用后按实际 usage 对账；并发请求不能穿透预算。
- [x] 响应未知或 usage 缺失时保留待对账预留，不能直接认定调用免费或自动退回。
- [ ] 增加全局费用阈值、异常告警和新付费调用停止开关。
- [x] 预算耗尽时仍允许读取已有会话和结果。

验收：多次调用和并发调用均受预算约束；消息次数限额与费用预算分别可审计。

#### 4.3 日志与指标

当前 `jobs.py`、`server.py` 的部分异常捕获只返回通用错误，缺少异常定位记录。

- [x] 贯通 `trace_id / workspace_id / turn_id / job_id / run_id / attempt_id`。
- [x] 服务端记录错误类别、异常栈、阶段与耗时；前端继续返回脱敏提示。
- [x] 监控排队时间、成功率、R 超时、模型错误、证据校验失败、缓存命中、token 与费用。
- [ ] 监控内存、磁盘和任务积压，设置基于目标运行环境的告警阈值。
- [x] 默认记录元数据；不直接把聊天、完整 prompt、原始响应、密钥写入普通运维日志。

验收：注入一次磁盘写入失败或上游结构错误，可以从任务 ID 定位具体阶段和异常；日志不泄露测试密钥。

#### 4.4 存储生命周期

- [x] 任务只保存结果引用或当前消息，不在多个完成任务中重复保存整段对话快照。
- [x] 会话消息、任务事件和列表支持分页；列表读取摘要索引。
- [x] 增加访客与会话存储字节配额，避免只限制对象数量。
- [x] 为匿名工作区、完成任务、缓存和审计记录分别定义 TTL、归档与删除策略。
- [x] 明确“删除聊天”是否保留研究记录及其问题文本，界面说明与实现保持一致。
- [x] 清理任务不得误删活动任务、被引用结果或需要保留的实验审计证据。
- [x] 清理不再使用的内存锁对象时，确保没有持有者或等待者。

验收：长会话不会让多个 job 重复占用整段历史内存；过期数据可按策略清理；备份和恢复流程经过演练。

建议发布门禁：

| 门禁 | 通过条件 |
|---|---|
| 语义保真 | 版本化评测集内，无严重静默替换、条件遗漏或反向筛选 |
| 执行恢复 | 幂等、断网、进程终止、重启和跨访客隔离用例通过 |
| 数值正确性 | 代表性真实 R 集成通过；独立数值验证状态有证据且明确披露 |
| 结果发布 | 被抑制/无效结果不进入答案、图表或导出；解释不改变证据 |

## 6. 当前不优先推进的事项

- 增加开放式代码执行、任意统计公式或模型自行选择的研究人群。
- 为了架构形式引入多个自主 Agent 或全面替换现有框架。
- 在没有评测和恢复机制前增加更多指标、年份或数据库。
- 为提高成功率而让独立盲测自动重试，或将缓存测量视为新实验。
- 将“现有单元测试全部通过”描述成真实模型或独立统计验证通过。

当前优先目标是：让已支持的分析准确表达用户需求，并在失败、重启和并发情况下保持结果与记录可解释。
